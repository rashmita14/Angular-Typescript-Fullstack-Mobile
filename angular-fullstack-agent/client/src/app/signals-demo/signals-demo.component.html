A TINY ANGULAR LESSON

Signals, in three steps

Click the counter, then open the browser console to see the effect run.

{{ count() }}
Computed: count × 2 {{ doubled() }}

Before: BehaviorSubject

count$ = new BehaviorSubject(0);
doubled$ = count$.pipe(
  map(count => count * 2)
);
count$.next(count$.value + 1);

Read with an async pipe or subscribe; remember to manage subscriptions.

Now: Signals

count = signal(0);
doubled = computed(
  () => this.count() * 2
);
this.count.update(n => n + 1);

Read by calling the signal; Angular tracks dependencies and updates the view.

effect() is for side effects, not derived values. Here it logs count changes; computed() derives the doubled value.

HOW ANGULAR KNOWS WHEN TO CHECK

OnPush + signals + zoneless

This counter component uses ChangeDetectionStrategy.OnPush. It is not continuously checked: Angular refreshes it when it has a reason to believe its view changed.

New input reference For object inputs, replace the object instead of mutating it in place.
Template or host event Clicking + runs a component event handler, so Angular checks the relevant view.
Template-read signal count() is read in this template; updating it marks this view for refresh.
Other Angular notifications async pipe emissions and markForCheck() also notify Angular.

What changes with zoneless?

Zone.js used to notice many browser tasks and prompt Angular to check. Zoneless removes that implicit scheduling: Angular schedules checks from framework notifications such as signal updates, bound events, markForCheck(), and the async pipe. OnPush is a per-component checking strategy; zoneless is application-wide scheduling. They work well together, but they are not the same feature. 

// Angular 20.2: opt in explicitly
providers: [
  provideZonelessChangeDetection()
]

This project uses Angular 22, where zoneless is the default; no provider is needed. In Angular 21+, provideZonelessChangeDetection() is optional and explicit. Avoid relying on Zone.js to detect arbitrary third-party or plain field mutations—use signals or call markForCheck() when integrating those updates.
